# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

School project + GitHub portfolio piece: finance modules, each showing a discrete model converging to a continuous one (limits), ending in a VaR-constrained portfolio allocation found via the Intermediate Value Theorem + bisection (Module 4: stocks + bank; Module 5: the best mix of stocks, gold, bonds and bank). The school requires **MATLAB**; Python is the reference implementation.

## Commands

```bash
pip install -r requirements.txt           # numpy, matplotlib, pytest
python main.py                            # prints all result tables, writes figures/*.png
python -m pytest                          # all tests (pytest.ini sets pythonpath=. and testpaths=tests)
python -m pytest tests/test_modules.py::test_var_root_hits_the_limit   # single test
```

MATLAB (from the `matlab/` folder): `run_tests` then `main` (figures go to `matlab/figures/`). MATLAB is not installed on the dev machine, so MATLAB changes cannot be run locally — review them carefully.

## Architecture

- `src/bisection.py` is the shared core: `bisection(fun, a, b)` returns `(root, history)` and raises `ValueError` when the IVT sign condition fails (it compares signs directly, never `fa * fm`, which can underflow to 0). It is used by `normal.norm_ppf` (inverse normal CDF), `risk.numerical_kelly_fraction` (root of g'), `risk.max_fraction_under_var` (root of VaR(f) − L), `risk.max_fraction_under_es` (root of ES(f) − L), `risk.value_at_risk_jump` (quantile of the crash mixture), `risk.max_fraction_under_var_jump` (root of VaR_jump(f) − L, so a bisection whose function is itself a bisection), `risk.kelly_fraction_jump` (root of the slope of the growth with crashes) and `portfolio.fund_fraction` (one bisection per fund in Module 5). The history rows `[a, b, mid, fun(mid)]` are printed in `main.py` as the IVT demonstration.
- All rates are continuously compounded (μ = 10% is 10.5% a year). The VaR root is unique for every horizon: VaR(f) = L is a quadratic in f whose roots have opposite signs (`risk.var_root_formula`, a check on bisection); the same concavity makes the ES root unique and Module 5 convex (one best mix).
- `src/normal.py` implements the normal CDF/PDF/PPF with `math.erf` on purpose — no scipy — so code ports to base MATLAB without the Statistics Toolbox.
- Module chain: `compounding.py` (1) → `option_pricing.py` (2) → `gbm.py` (3) → `risk.py` (4). Module 4's closed-form wealth/VaR formulas assume the continuous limits established in modules 1 and 3. Module 4b (fat tails, `main.module4b_crashes`) adds Merton-style crashes: size J, rate λ, drift compensated by λJ so the average return stays μ. With λ = 0 every crash function must equal its Module 4 twin (tested). Crashes lower the long-run growth (`growth_rate_jump`, 6.94% → 6.76% at f_VaR) and the Kelly fraction (`kelly_fraction_jump`, 1.75 → 1.4098); `optimal_fraction_jump` = min(f*_crash, f_crash, f_max). Expected Shortfall (`expected_shortfall`, `expected_shortfall_jump`, `empirical_es`, `portfolio_es`) is the average loss in the worst 1 − α: 19.76% at f_VaR (23.48% with crashes), f_ES = 0.546928. Module 5 (`portfolio.py`, `main.module5_portfolio`): a fixed mix d of the risky assets is one fund (μ_d = r + d·(μ − r), σ_d = √(dᵀCd)), so `fund_fraction` is Module 4 for that fund (f = min(f*, f_VaR, 1)); `best_mix_under_var` tries every mix on the 1% grid `mix_grid(3)` (5,151 funds, fixed order: first share slowest, tested) and keeps the fastest-growing one. No borrowing, no short selling. A stocks-only mix must equal Module 4 (tested). Module 5's limit: `fund_fractions` (vectorized, f_VaR from the quadratic formula) powers `best_mix_on_grid(steps)` (nested grids 25 → 1600: best growth never goes down) and `refine_best_mix` (zoom in: exact best 72.9/4.9/22.2, g = 7.46887%); `near_optimal_ranges` shows the flat top (73% stocks, 1–7% gold within 0.01%/yr). Gold/bond numbers in `main.py` match the website's "Normal" market.
- `gbm.ks_distance_to_gbm` computes the KS distance **exactly** from binomial probabilities (no Monte Carlo), so its convergence plot is noise-free.
- `main.py` holds all model parameters as constants at the top (savings, option, market, risk-limit) and one function per module that prints tables and saves one figure.

## Python ↔ MATLAB parity

`matlab/` mirrors `src/` one function per `.m` file with the **same names and argument order**; `matlab/main.m` mirrors `main.py` and `matlab/run_tests.m` mirrors `tests/test_modules.py`. When changing a Python function, make the same change in its `.m` file (and vice versa). Differences to keep in mind:
- Python random functions take an `rng` argument; MATLAB versions drop it and use the global stream (`rng(seed)`), so Monte Carlo numbers differ between languages while deterministic numbers must match.
- `quantile_linear.m` reimplements `numpy.quantile` (linear interpolation) to avoid the Statistics Toolbox.
- Keep Python code MATLAB-portable: plain functions, numpy arrays only, no classes/pandas/scipy.

- **`marketStates(p, lam, J)`:** builds the four states. Today's state (`p.mood`) has exactly `p.avg0`, the typed interest rate and inflation; other states shift them by the `MOODS` differences from today's state. Risks are `p.sig0` scaled by each state's `MOODS` ratio to normal. Crashes use the rate and size from More settings (`crashSettings`) and multiply stocks by 1 + J and gold/bonds by `CRASH_SAFE`; every asset's drift is compensated (`muc` = `avg` − ln(1 + shock·(crash − 1))), so each average return stays the table value (tested: gold 5.08% with crashes on). With markets not changing, no crashes and no events, the years are the user's GBM plus savings account exactly (tested); the plan is rebalanced once a year, so the strike rate is close to (slightly below) 1 − α, not exactly it. `mathState(s)` gives the bell-curve numbers (full average drifts `avg`) used by `bestMix`.
- **Uploaded data:** `series[i]` holds the prices of asset i (one upload row each; a file with columns named like stocks/gold/bonds, `ASSET_WORDS`, fills several rows). The stock file sets the stock inputs and drives the history check and real years; gold/bond files give `p.est` (gold: only σ, since gold's average is inflation + 2%; a stock or bond average is used only when no P/E or yield is typed). Average returns are blended with a long-run premium over the savings rate (`usedMu`, precision weight `dataWeight` with `PRIOR_SD` = 3%); σ comes straight from the data. `estimateRho` measures correlations from shared months (pulled toward the currency's typical correlations, weight n/(n + 36)) into `p.rho`, which every state, `mathState`, `fundOf`, `portfolioVar`, `riskEstimate`, `bestMixCrash` and `generateYears` use (cache keys include it). `stockSignal` feeds `todayMarket` and `#marketNote` explains the result. Real stock years already contain real crashes and markets, so `lifeSettings()` then uses states without crashes and no market changes (gold, bonds, savings stay at today's values); `settingsText` says so. 
- **Near-optimal range:** `bestMix` also returns `near`, each share's range over the splits within `NEAR` = 0.1%/yr of the best growth; `#planNear` shows it so the exact numbers read as a rough guide.
- **Crash-safe plan:** `bestMixCrash` (JS only) uses `riskEstimate` (one possible crash year) on a 2% grid; growth includes the crash. Shown only when crashes are on.
- **`set.events`:** with `events` off, the life events are drawn but ignored, so seeds stay comparable. Strikes (years over the limit) are counted; nobody stops.
- **Moods:** the `MOODS` values are templates (shifts for the stock, rate and inflation, absolute values for gold and bonds). They are illustrative, simulated simple yearly rates for universal assets (stocks, gold, bonds, savings account), roughly like long-run developed-market history, not data or any one country. They are converted to continuous rates (`rc`, `muc` = ln(1 + x)) before use. The crash card (Module 4b) uses the crash-aware Kelly `kellyFractionJump` in `crashSolve`.
- **`portfolioVar`:** the multi-asset generalisation of `value_at_risk`. With only stocks it must equal `valueAtRisk`.
- **Markets change over time:** each year's state (`regime`) follows the illustrative Markov chain `TRANSITION` over `REGIME_KEYS`. It is drawn in `generateYears` from the seeded rng.
- **Fair comparisons:** every strategy goes through `stepYear` on the same pre-generated, seeded `years`. Keep it that way.
