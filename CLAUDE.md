# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

School project + GitHub portfolio piece: finance modules, each showing a discrete model converging to a continuous one (limits), ending in a VaR-constrained portfolio allocation found via the Intermediate Value Theorem + bisection (Module 4: stocks + bank; Module 5: the best mix of stocks, gold, bonds and bank). The school requires **MATLAB**; Python is the reference implementation.

## Commands

```bash
pip install -r requirements.txt           # numpy, matplotlib, pytest
python main.py                            # prints all result tables, writes figures/*.png
python -m pytest                          # all tests (pytest.ini sets pythonpath=. and testpaths=tests)
python -m pytest tests/test_modules.py::test_var_root_hits_the_limit   # single test
```

MATLAB (from the `matlab/` folder): `run_tests` then `main` (figures go to `matlab/figures/`). MATLAB is not installed on the dev machine, so MATLAB changes cannot be run locally — review them carefully.

## Architecture

- `src/bisection.py` is the shared core: `bisection(fun, a, b)` returns `(root, history)` and raises `ValueError` when the IVT sign condition fails (it compares signs directly, never `fa * fm`, which can underflow to 0). It is used by `normal.norm_ppf` (inverse normal CDF), `risk.numerical_kelly_fraction` (root of g'), `risk.max_fraction_under_var` (root of VaR(f) − L), `risk.max_fraction_under_es` (root of ES(f) − L), `risk.value_at_risk_jump` (quantile of the crash mixture), `risk.max_fraction_under_var_jump` (root of VaR_jump(f) − L, so a bisection whose function is itself a bisection), `risk.kelly_fraction_jump` (root of the slope of the growth with crashes) and `portfolio.fund_fraction` (one bisection per fund in Module 5). The history rows `[a, b, mid, fun(mid)]` are printed in `main.py` as the IVT demonstration.
- All rates are continuously compounded (μ = 10% is 10.5% a year). The VaR root is unique for every horizon: VaR(f) = L is a quadratic in f whose roots have opposite signs (`risk.var_root_formula`, a check on bisection); the same concavity makes the ES root unique and Module 5 convex (one best mix).
- `src/normal.py` implements the normal CDF/PDF/PPF with `math.erf` on purpose — no scipy — so code ports to base MATLAB without the Statistics Toolbox.
- Module chain: `compounding.py` (1) → `option_pricing.py` (2) → `gbm.py` (3) → `risk.py` (4). Module 4's closed-form wealth/VaR formulas assume the continuous limits established in modules 1 and 3. Module 4b (fat tails, `main.module4b_crashes`) adds Merton-style crashes: size J, rate λ, drift compensated by λJ so the average return stays μ. With λ = 0 every crash function must equal its Module 4 twin (tested). Crashes lower the long-run growth (`growth_rate_jump`, 6.94% → 6.76% at f_VaR) and the Kelly fraction (`kelly_fraction_jump`, 1.75 → 1.4098); `optimal_fraction_jump` = min(f*_crash, f_crash, f_max). Expected Shortfall (`expected_shortfall`, `expected_shortfall_jump`, `empirical_es`, `portfolio_es`) is the average loss in the worst 1 − α: 19.76% at f_VaR (23.48% with crashes), f_ES = 0.546928. Module 5 (`portfolio.py`, `main.module5_portfolio`): a fixed mix d of the risky assets is one fund (μ_d = r + d·(μ − r), σ_d = √(dᵀCd)), so `fund_fraction` is Module 4 for that fund (f = min(f*, f_VaR, 1)); `best_mix_under_var` tries every mix on the 1% grid `mix_grid(3)` (5,151 funds, fixed order: first share slowest, tested) and keeps the fastest-growing one. No borrowing, no short selling. A stocks-only mix must equal Module 4 (tested). Module 5's limit: `fund_fractions` (vectorized, f_VaR from the quadratic formula) powers `best_mix_on_grid(steps)` (nested grids 25 → 1600: best growth never goes down) and `refine_best_mix` (zoom in: exact best 72.9/4.9/22.2, g = 7.46887%); `near_optimal_ranges` shows the flat top (73% stocks, 1–7% gold within 0.01%/yr). Gold/bond numbers in `main.py` match the website's "Normal" market.
- `gbm.ks_distance_to_gbm` computes the KS distance **exactly** from binomial probabilities (no Monte Carlo), so its convergence plot is noise-free.
- `main.py` holds all model parameters as constants at the top (savings, option, market, risk-limit) and one function per module that prints tables and saves one figure.

## Python ↔ MATLAB parity

`matlab/` mirrors `src/` one function per `.m` file with the **same names and argument order**; `matlab/main.m` mirrors `main.py` and `matlab/run_tests.m` mirrors `tests/test_modules.py`. When changing a Python function, make the same change in its `.m` file (and vice versa). Differences to keep in mind:
- Python random functions take an `rng` argument; MATLAB versions drop it and use the global stream (`rng(seed)`), so Monte Carlo numbers differ between languages while deterministic numbers must match.
- `quantile_linear.m` reimplements `numpy.quantile` (linear interpolation) to avoid the Statistics Toolbox.
- Keep Python code MATLAB-portable: plain functions, numpy arrays only, no classes/pandas/scipy.

## Web pages

`web/index.html` (explainer) and `web/investor.html` (real-life tool) use no external libraries (the same hand-written SVG `drawChart`, the same light/dark colour tokens) and re-implement the deterministic formulas in JavaScript: `bisection`, `normPpf`, `growthRate`, `kellyFraction`, `valueAtRisk`, `poissonPmf`, `jumpLogWealthCdf`, `valueAtRiskJump`, `maxFractionUnderVar`, `quantileLinear`, `fundOf`, `fundFraction`, `bestMix` and `portfolioVar` mirror `src/bisection.py`, `src/normal.py`, `src/risk.py` and `src/portfolio.py`; `upProbability`, `walkLogReturnDistribution`, `gbmLogReturnCdf` and `ksDistanceToGbm` (index.html only) mirror `src/gbm.py`. index.html also has `growthRateJump`, `expectedShortfall`, `mixGrid`, `varRootFormula`, `fundFractionFormula` and `refineBestMix`; investor.html has `kellyFractionJump` and `esOf` (ES of a bell-curve year; `bestMix` and `mixStats` return `es`). Keep them in sync when the Python changes. The JS numbers must match Python, for example f_VaR = 0.705014 with the default parameters and f_max = 2, f_crash = 0.617447 with λ = 0.1, J = −0.25, and the default plan 73% stocks / 4% gold / 23% bonds with g = 0.0746824 (JS `erf` is an approximation, so agreement is to about 6 digits). `index.html` has one section per module (1, 2, 3, 4, 4b, 5), each with one big slider for the limit variable (Module 5 has two: bonds in the mix, and the search step 20% → 1% whose triangle of dots closes in on `TRUE_BEST` = `refineBestMix`, 7.4689%); its numbers must match Python too (KS distances, f_VaR, f_crash, the 73/4/23 best mix, the grid bests of `best_mix_on_grid`), and tests set `window.EXPLAINER_NO_ANIM = true`. Uploaded CSVs are parsed client-side only, so never add network calls. There is no JS test runner; verify by opening the page in headless Edge with an isolated `--user-data-dir` and an injected test script.

`investor.html` is one minimalist page, no tabs. At first only the inputs card shows (no heading): money, yearly saving, interest rate, inflation, market buttons, risk choice (Careful / Balanced / Bold, no percentages shown), everything else in a closed "More settings" `<details>` (years, confidence, the optional **guess**, stock numbers, bond yield, surprises, CSVs for stocks, gold and bonds; there is no goal setting), and a **Calculate my plan** button. The guess (stocks/gold/bonds sliders, savings = the rest; `guessW()`) is off by default behind the `#useGuess` checkbox; when it is off `cur.guess` is `null` and the page shows only the math (no guess table, guess row or who-ended-ahead bar). Inputs only run `onInputChange()` → `renderInputs()` (live, never reads `cur`); the button runs `calculate()`, which builds everything once into `cur` (`compute()`, including snapshots of the uploaded `data` and the surprise switches) and reveals `#results`. Changing an input afterwards dims the results (`.stale`) until the button is pressed again. Results: (2) the plan (`bestMix` for today's market, a one-sentence summary in money (`#planSentence`), donut, tiles, "Your guess vs the math" via `mixStats`, crash-safe callout); (3) the plan in real life: main strategies are your plan, your guess (only if made) and the savings account (`main: true` in `lifeStrategies`), extras (crash-safe, stocks + savings only, all stocks, all gold) only in the closed "Compare more strategies" table; `renderLifeMany` runs the 500 seeds in chunks (returns a promise, `life.many`) and shows who ended ahead, plan or guess; (4) "How we found your plan", closed `<details>` with the math (mix bars, bell curve, IVT + bisection, Module 4b crash card, history check). Resizing redraws charts only when the `innerWidth < 560` switch in `drawChart` flips, without recomputing.
- **Rates:** every rate typed on the page (bank interest, stock average return) is an ordinary yearly rate; `params()` converts it with ln(1 + x) like `MOODS`, so the "markets used" table shows exactly what was typed. The stock default is 10.5% (≈ e^0.1 − 1), which keeps the default plan 73/4/23 (g = 0.0745597); typing 100(e^0.10 − 1) and 100(e^0.03 − 1) reproduces Python's g = 0.0746824 exactly. CSV estimates are written back as e^μ − 1 (`setStock`).
- **Risk choice:** `ui.risk` is careful / balanced / bold; `params()` turns it into the loss limit `p.L` via `riskLimit(p, risk)`. Careful = 5% and Balanced = 15% in every market (`RISK_LIMITS`: how much a person can lose is about the person, not the market). `riskTop(p)` = `bestMix(m, 1, alpha)` is the plan with no limit (the fastest-growing mix without borrowing), and Bold's limit is its exact bad-year loss (at least 2%), so the Bold plan *is* that mix (22.05% in a normal market; never round it, rounding down made Bold 99.8% stocks). When the top's VaR is within the person's limit (calm, crisis), Balanced gives the same plan as Bold and `#riskText` says so. `#riskText` must describe VaR correctly: "only about 1 year in 20 should lose more than …", never "you lose at most". `topReason(top, m)` says why it stops there, and the Bold note and the plan's explanation must use it: "borrow" when it is already 100% in the riskiest asset (calm and normal markets: 100% stocks; with borrowing growth would still rise up to the Kelly point f* = 1.75, so do **not** say more risk grows slower), "drag" when a riskier mix exists but grows slower (crisis, high inflation), "kelly" when more of the same mix would grow slower (f* < 1). The money meaning is shown under the buttons, and a disclaimer only when Bold is picked. Adding riskier assets does not remove the top (it only moved 22% → ~25% in a test) and would break Python parity.
- **Language:** the `ENG | TUR` switch (`.lang`, top-right) sets `LANG` (remembered in `localStorage` `investorLang`, else the browser language). Static text is English in the HTML with `data-i18n="key"` (and `data-i18n-aria`) and Turkish in `I18N_TR`; text built in code uses `tx(en, tr)`, and asset/market words come from `aName`/`aLow`/`aIn` and `moodName`/`moodA`/`moodIn`/`moodYear` (Turkish needs case endings, so whole phrases, not words, are translated). `pct`/`num`/`fix` write Turkish numbers (%7,5, 10.000); input values keep a dot. `setLang` redraws everything from `cur` without recalculating, like the currency. Any new user-facing text needs both languages; the English output must stay as it was.
- **Currency:** the `#currency` picker (default $) only changes how amounts are written: `money()` adds `sym()`, chart axes use plain `num()` and name the currency in the axis label (`inSym`). Changing it redraws the results from `cur` (and `life.lastMany`) without recalculating or dimming them.
- **`mixStats(w, m, alpha)`:** bell-curve growth, VaR and ES of any split, built from `fundOf` + `growthRate` like `fundFraction`, so `mixStats(plan.w)` equals `plan.g`, `plan.var` and `plan.es` exactly (tested). The plan sentence also says what the bad years lose on average (ES).
- **Game score (`#lifeGame`):** the guess challenge is a game. Score = share of the 500 futures where the guess ends with more money than the plan, ties count half (the plan's own split scores exactly 50%, tested). A try counts toward the best only if `guess.var <= p.L` (otherwise "✗ doesn't count"). `recordTry` runs once per calculation at the end of `renderLifeMany` and is stored in `life.lastMany.game`; `showLifeMany` → `renderGame` only displays it, so currency/language redraws never add a try, and pressing the button again with the same split is not a new try. The best is kept per settings (`gameKey()`: a hash of `cur.p`, crash, surprise switches and uploaded data) in `localStorage` `investorBest` (max 30 settings, all in try/catch; without storage it still shows the score). Without a guess it shows an invitation; its button (`[data-try]`) opens More settings, turns the guess on and focuses `#gStock`.
- **Arcade "Fund Manager" (`#arcade` `<dialog>`, opened by the 🕹️ `#arcadeOpen` box next to the language switch in `.topbar`):** a separate neon game, independent of the inputs. You manage $10,000 for 5 years (`ARC_YEARS`) with 3 hearts. Each year shows the market (first year random, then `nextRegime` on `TRANSITION`; its `MOODS` numbers as they are, `arcMarket`), you split the money on a donut dial (`arcDialSvg`/`arcDialWire`: three dots cut the ring at a ≤ b ≤ c, slices stocks/gold/bonds/savings; drag a dot, click the ring to move the nearest dot, arrow keys on a focused dot; tied dots are picked by the drag direction) with a live chance of a losing year (`arcOdds`: log-wealth normal, P = Φ(−g/(f·σ_d))), then the year plays month by month (`arcSimYear`: correlated monthly GBM with `RHO`, a crash month with probability `shock` (stocks ×0.75, gold/bonds `CRASH_SAFE`), drifts compensated like `marketStates`). A year that ends below its start costs a heart; 0 hearts = the animated "YOU ARE FIRED!" screen. The rival "the Quant" plays `bestMix(m, 0, 0.8)` (fastest growth with a losing year at most 1 in 5; its 20% matches the simulation) on the same months; `arcVerdict` tags your split Most efficient / Too careful / Bold / Too risky against it. The end screen: Promoted (≥ 99.5% of the Quant), keep your job (above the savings account) or barely survived; best final money in `localStorage` `investorArcadeBest`. The character is an inline SVG (`arcGuy`: happy/nervous/panic/win/fired faces by hearts), the boss lines are in `ARC_BOSS_MOOD`/`arcBossYear`; animations stop under `reduceMotion()` (years finish at once). Closing the dialog mid-year finishes the year. All text via `tx`; it stays dark in both themes.
- **`marketStates(p, lam, J)`:** builds the four states. The typed interest rate and inflation belong to the picked market (`p.mood`); other states shift them by the `MOODS` differences. The stock μ, σ are for a normal market and are shifted the same way. Picking a market button fills in typical rate/inflation (`pickMood`) only until the person types their own (`ui.typed`, cleared by Reset); typed numbers are never overwritten. Crashes use the rate and size from More settings (`crashSettings`) and multiply stocks by 1 + J and gold/bonds by `CRASH_SAFE`; every asset's drift is compensated (`muc` = `avg` − ln(1 + shock·(crash − 1))), so each average return stays the table value (tested: gold 5.08% with crashes on). With markets not changing, no crashes and no events, the years are the user's GBM plus savings account exactly (tested); the plan is rebalanced once a year, so the strike rate is close to (slightly below) 1 − α, not exactly it. `mathState(s)` gives the bell-curve numbers (full average drifts `avg`) used by `bestMix`.
- **Uploaded data:** `series[i]` holds the prices of asset i (one upload row each; a file with columns named like stocks/gold/bonds, `ASSET_WORDS`, fills several rows). The stock file sets the stock inputs and drives the history check and real years; gold/bond files give `p.est` (normal-market values, shifted to other states like the stock numbers). Average returns are blended with a long-run premium over the savings rate (`usedMu`, precision weight `dataWeight` with `PRIOR_SD` = 3%); σ comes straight from the data. `estimateRho` measures correlations from shared months (pulled toward `RHO`, weight n/(n + 36)) into `p.rho`, which every state, `mathState`, `fundOf`, `portfolioVar`, `riskEstimate`, `bestMixCrash` and `generateYears` use (cache keys include it). `detectMarket` reads today's market from the stock prices (last 3 months' swings vs the whole file, fall from the 1-year high, typed inflation); uploading picks it via `pickMood` and `#detectNote` explains it. Real stock years already contain real crashes and markets, so `lifeSettings()` then uses states without crashes and no market changes (gold, bonds, savings stay in the picked market); `settingsText` says so. With no files and no bond yield, the page must give exactly the old numbers (73/4/23, g = 0.0745597).
- **Bond yield:** the optional `#bondYield` (`p.bondY`) is today's, so it is the bonds' average in the picked market (other states shifted), overriding the table or a bond file's average.
- **Near-optimal range:** `bestMix` also returns `near`, each share's range over the splits within `NEAR` = 0.1%/yr of the best growth; `#planNear` shows it so the exact numbers read as a rough guide.
- **Crash-safe plan:** `bestMixCrash` (JS only) uses `riskEstimate` (one possible crash year) on a 2% grid; growth includes the crash. Shown only when crashes are on.
- **`set.events`:** with `events` off, the life events are drawn but ignored, so seeds stay comparable. Strikes (years over the limit) are counted; nobody stops.
- **Moods:** the `MOODS` values are templates (shifts for the stock, rate and inflation, absolute values for gold and bonds). They are illustrative, simulated simple yearly rates for universal assets (stocks, gold, bonds, savings account), roughly like long-run developed-market history, not data or any one country. They are converted to continuous rates (`rc`, `muc` = ln(1 + x)) before use. The crash card (Module 4b) uses the crash-aware Kelly `kellyFractionJump` in `crashSolve`.
- **`portfolioVar`:** the multi-asset generalisation of `value_at_risk`. With only stocks it must equal `valueAtRisk`.
- **Markets change over time:** each year's state (`regime`) follows the illustrative Markov chain `TRANSITION` over `REGIME_KEYS`. It is drawn in `generateYears` from the seeded rng.
- **Fair comparisons:** every strategy goes through `stepYear` on the same pre-generated, seeded `years`. Keep it that way.
- **Animations:** they must respect `prefers-reduced-motion`. Tests set `window.INVESTOR_NO_ANIM = true`.
